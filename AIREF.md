## 5. Important Patterns, Conventions, and Architecture Decisions

### General Architecture
- **Monorepo-style split**: separate `client/` and `server/` with independent `package.json` files
- **REST API**: backend exposes `/api/*` endpoints consumed by frontend
- **JWT Authentication**: access token stored in `localStorage`, sent via Axios interceptor
- **Role-Based Access Control (RBAC)**: roles include `Super Admin`, `Admin`, `Manager`, `Support Staff`, and customer roles
- **MVC-like structure** on the backend: routes → controllers → services → models

### Frontend Conventions
- Functional React components with hooks
- `export default function ComponentName()` pattern
- API calls centralized through `API` service
- Toast notifications via `react-hot-toast`
- Icons imported individually from `lucide-react`
- Tailwind utility classes used extensively; dark-themed dashboard

### Backend Conventions
- CommonJS (`require`) on the server
- Async/await with try/catch in controllers
- `res.data.success` response shape commonly expected by frontend
- Password hashing with `bcryptjs`
- Mongoose models define all domain entities

### AI Assistant (Perincle)
- Name and builder identity are hardcoded in `SYSTEM_PROMPT`: built by **OTECH (OTECH IQ)**
- 5-day conversation retention enforced in both frontend and backend
- Support mode toggle: AI vs human/live support
- Knowledge documents stored in MongoDB (`KnowledgeDocument`)
- Global on/off switch via `SystemSetting`

### SMS / Voice Conventions
- Sender ID `FASREACH` is reserved for system admins
- Regular users must register and get a Sender ID approved
- Multi-provider gateway abstraction allows switching providers
- Cost calculator computes SMS units based on message length/encoding
- Voice messages support WAV/PCM upload and text-to-speech

### Security
- Helmet for headers
- CORS configured
- Rate limiting on API routes
- Input sanitization expected but verify in implementation
- API keys for developer access

## 7. Important Notes for an AI Assistant Working on This Codebase

1. **Never change the AI identity**: Perincle must always identify as built by **OTECH (OTECH IQ)** for FasReach. Do not alter this unless explicitly requested.

2. **Role-based permissions matter**: Admin pages and certain API actions are gated by role. Test changes with both admin and non-admin users.

3. **FASREACH Sender ID is reserved**: Code explicitly blocks non-admin users from sending with `FASREACH`. Keep this guard in place.

4. **Dual cost calculator**: Cost logic exists in both `client/src/utils/costCalculator.js` and `server/src/utils/costCalculator.js`. Keep them synchronized to avoid billing discrepancies.

6. **API path assumptions**: The frontend expects `/api/*` routes. `vercel.json` rewrites these to the Render backend URL (`https://bulk-sms-platform.onrender.com/api/*`).

7. **Subdomain SSO**: `ProductHub.jsx` implements subdomain redirects (`sms.fasreach.com`, `voice.fasreach.com`) with `sso_token`. Be careful when editing routing or auth context.

8. **No visible linting config in server**: The client uses ESLint, but the server package does not show a lint script. Add linting carefully if needed.

11. **Existing scripts are operational**: Files in `server/src/scripts/` (delete user, inspect DBs) are powerful maintenance tools—use with caution.

12. **Voice file format**: `VoiceSMS.jsx` includes custom WAV conversion from Web Audio API. Any changes to audio handling should preserve PCM WAV output expected by the provider.

13. **Translations and TTS**: The backend uses `@vitalets/google-translate-api` and has TTS test files. Be aware of rate limits and provider API keys.

14. **When adding features**, follow the established pattern: add route → controller → service/model → frontend page/component, and use the existing `API` service and toast notifications.

15. **No formal tests**: There is no automated test suite. Validate changes manually and consider adding tests for critical billing/auth paths.
